RideFlowIntelligent ride dispatch, fleet management and dynamic pricing simulator

A Java 21 operations simulator for a fictional 20 km city: which driver gets the ride, what the trip costs, and what stops one driver being booked twice. Built with Spring Boot, raw JDBC, MySQL and JavaFX.

Use it two ways: book a ride as a passenger, or watch the whole city from the operator console below.

      A browser port of RideFlow's core rules: weighted-fair and nearest-driver scoring, the aging priority queue, per-zone surge, a 10 km pickup radius and 15-minute expiry. Demand rates are scaled for a 20-driver fleet; one tick is one simulated minute. The real application runs these rules in Java against MySQL.

      One ride, from request to completion

      RideFlow is not a booking app. It is the operator's side of a ride-hailing platform, with synthetic riders, drivers, traffic and fares, so every decision can be paused, stepped and explained.

      1

      Validate and lock the fare

      Coordinates must sit inside the 100×100 city. The quote is computed from distance, duration and zone surge, then stored and never changed.

      2

      Queue the request

      A PriorityQueue orders requests by type plus waiting time, so a standard ride is never starved by a stream of priority ones.

      3

      Select and reserve

      Available drivers within 10 km are scored. The best one is reserved in a single MySQL transaction.

      4

      Complete and release

      Each tick moves the driver to the pickup, then the destination. The driver is freed, earnings and analytics update.

      QUEUED→ASSIGNED→IN_PROGRESS→COMPLETED  driver:AVAILABLE→RESERVED→ON_TRIP→AVAILABLE
      25

      zones in a 20×20 km city

      A 5×5 grid; one coordinate unit is 0.2 km, roads are 1.25× straight-line distance at 30 km/h.

      1 tick

      = one simulated minute

      Start, pause, resume, step and reset. A seeded generator makes every scenario repeatable.

      5

      demand scenarios

      Normal, rush hour, low supply, high demand and balanced market, plus rush-hour, rainstorm and fleet-mobilisation shocks.

      Which driver should get the ride?

      The nearest driver is not always the fairest choice. Weighted fair dispatch gives a bounded credit for idle time, so a driver who has waited long is not bypassed forever for someone a few hundred metres closer.

      score = pickupETA − 0.05 × min(idleMinutes, 30)   // lower wins

      The idle credit is capped at 1.5 minutes, so fairness can never override a large distance. Ties break on driverId for reproducible results. Nearest driver uses pickup ETA alone.

      How a ₹151.00 fare becomes ₹264.25

      Surge is computed per zone at the moment of quoting, clamped between 1.0× and 2.5×, and calculated with BigDecimal. The quote is locked into fare_quotes when the ride is booked.

      Two requests, one driver, no double booking

      Two dispatch threads can pick the same best driver at the same instant. RideFlow guards the reservation with a conditional update inside one JDBC transaction.

      UPDATE drivers
   SET status = 'RESERVED', version = version + 1,
       updated_at = CURRENT_TIMESTAMP
 WHERE driver_id = ? AND status = 'AVAILABLE';
-- affectedRows == 1  → insert assignment, commit
-- affectedRows == 0  → rollback, try next candidate

      Verified by ConcurrentDispatchTest: 2 competing attempts, 1 successful reservation, 1 active assignment.

      Thread 1: ride #1041

      1. Begin transaction
      2. Pick driver #108
      3. UPDATE … WHERE status = 'AVAILABLE'
      4. 1 row updated
      5. Insert assignment, commit

      Thread 2: ride #1042

      1. Begin transaction
      2. Pick driver #108
      3. UPDATE … WHERE status = 'AVAILABLE'
      4. 0 rows: already RESERVED
      5. Rollback, retry next driver
      Result: one driver, one active ride.

      Run it locally

      Needs JDK 21+ and Maven 3.8+. Docker is optional: without MySQL the server falls back to an in-memory MySQL-compatible database.

      git clone https://github.com/shashwatt22/rideflow.git
cd rideflow
mvn clean install            # build + all tests

docker compose up -d         # optional: MySQL 8

cd rideflow-server
mvn spring-boot:run          # http://localhost:8080
                             # Swagger: /swagger-ui.html
cd ../rideflow-desktop
mvn javafx:run               # operator console

      On Windows, scripts\run_all.cmd starts the server and the console together.

      Open this website on localhost

      scripts\run_website.cmd                 # Windows: opens http://localhost:8000
python -m http.server 8000 -d docs      # any OS, then visit http://localhost:8000

      The site has no build step: double-clicking docs/index.html also works offline, apart from the web fonts.
